# JobFray geocoding provider review

Reviewed November 24, 2026. Implementation is local only. No geocoding request, account creation, purchase, Render change, database operation, deployment or Stripe connection was made. Historical Phase 5/6A reports remain unchanged as evidence of their original implementation.

## Decision and requirements

Use **Geocodio Pay-as-you-go** for the current US-only directory. Its published pricing offers 2,500 free credits each day, then $1 per 1,000 credits; one forward lookup is one credit when no optional appends are requested. This has no monthly subscription minimum and fits an initially small, irregular workload. It is not the cheapest option at every sustained volume.

The [Geocodio terms, section 8.4](https://www.geocod.io/terms-of-use) permit retaining and using results during and after the agreement, subject to the underlying data-source conditions and law. The US forward-geocoding storage summary permits permanent storage. This supports JobFray's commercial application, stored coordinates and map-free search/radius calculations without licensing an embedded map. This is use of geocoding results in JobFray, not resale of access to the provider's API. Underlying-source attribution obligations still apply; review the [US data sources](https://www.geocod.io/data-sources) for the account's use. No new data-source rights are asserted for existing Mapbox-derived coordinates.

## Implementation and migration

`GeocodioAdapter` replaces the Mapbox adapter and still implements `Geocoder.zip()` and `Geocoder.address()`, returning only `{ latitude, longitude }`. Requests explicitly select USA. Country, numeric ranges, confidence, exact ZIP correspondence and street-level precision are checked. A ZIP centroid cannot authorize an exact service address. Multiple candidates fail closed, even if the provider considers both strong; this conservative ambiguity rule can reject otherwise valid multi-source results and must be assessed in later real-provider acceptance.

ZIP-only caching remains bounded to 256 entries and 24 hours. Address lookups are not cached. Raw responses, sources and normalized addresses are discarded after validation; API keys use a header and never enter request URLs. Errors stay sanitized and the existing eight-second, bounded-response, no-redirect transport and provider-operation gate are retained. No customer names, phone numbers, notes or images are sent. URLs contain the necessary lookup input; do not log request URLs or Authorization headers in production infrastructure.

Directory projection, coordinate schema/storage, private-base-to-public-ZIP substitution, approximate discovery distance, Haversine distance in miles, and exact service-radius enforcement were not changed. No migration or coordinate rewrite is needed. Existing coordinates retain their original licensing/provenance: do not treat a provider switch as retroactive permission to reuse Mapbox results. Inventory and separately approve any necessary re-geocoding before public release; no stored data was inspected or changed here.

`MAPBOX_ACCESS_TOKEN` and `MAPBOX_PERMANENT_GEOCODING` are no longer read or required by the current application. Remote values are **not removed**. Old ignored owner-run Render artifacts describe the retired provider and must not be used for this migration; their manifest-hash preflight rejects changed contracts. No Render script was executed or remote variable changed by this assignment.
